# 薄 skill 原型与盲测（2026-11-09）

接 [skill-spike-2026-11-09.md](skill-spike-2026-11-09.md)。上一份验证了「插件引擎能原样搬出插件」；这一份验证另一条路：不搬引擎，做一个薄 skill，让 agent 直接读页面、自己拼配置，再交给一个通用采集器跑。

## 原型

位置：`.codex-tmp/datalens-skill/`（已 gitignore，里面单独 `git init`，以后可以直接搬成独立仓库）。只依赖 Playwright，不打包 core。共 1123 行：

## 过拟合审查

开测前派一个 agent 审查 skill 文本有没有对着演练场写。它找出 10 处泄题，例如报告示例「标称 160 实际 123」就是 E03 的答案，`#albums .album` 是 A03 的原样标记，`.pager a.arrow:last-child` 是 D07 的答案，C11 的权益条目文案几乎逐字照抄。全部改成了与演练场无关的例子，干扰控件清单也删到只剩原则。脚本方面同时修了：`data:` 图片一律当占位图（会误删真实的内联缩略图）、locale 写死中文、翻页之间没有间隔、等待时长贴着某个 mock 的延迟。

## 盲测

- 14 个 case，覆盖晚渲染、虚拟列表、混合 class 表格、详情页小列表、合并单元格、展开全部、干扰控件、翻页后包装层消失、12 页数字分页、内部滚动容器、分两批到达、弹窗锁滚动、验证码墙（留出集）、续载挂起。
- 每个 case 派一个独立 agent（Opus），只给它 skill 路径、一句中文用户请求和一个短链（`/t/<随机码>`，不透露 case 名）。禁止读 skill 以外的文件，禁止 curl 和其他浏览器工具。
- 由评分脚本按标准答案判对错：行数等于 expectedRows，每行都含该 case 的数据行前缀，且没有重复行。

### 速度与成本

- 采集器运行：单页 2–4 秒（引擎不调 AI 时约 60 秒），12 页翻页 29 秒，虚拟列表 200 行 100 秒（每次只滚半屏）。
- 每个 agent 从开始到交付：47–175 秒，7–14 次工具调用，约 10 万 token。这个数包括系统提示词和 skill 文档；这是用户自己的模型额度，不是 DataLens 的成本。

## 这次结果不能说明的

1. **同分布**。references 是从这套演练场的 pattern 写出来的。审查后去掉了逐字的答案，但 pattern 本身仍被描述过。14 个里只有 F04-002 是留出集变体。这个 14/14 是同分布成绩。
2. **mock 很简单**。大多数页面每行只有 2 个字段。真实网站的字段又多又乱，评分也只看行数和行前缀，没有逐列核对字段对不对。C11 那类字段错位陷阱不在这次的评测集里。
3. **mock 会暴露参数**。有几个 agent 从页面内联脚本里读到了 `TOTAL = 40`、`hangAfter = 3` 这类参数。它们是在采完之后拿来佐证停机判断，行数并没有因此改变，但停机判断的把握度被抬高了。真实网站不会这样写。
4. **没有测要登录的站、详情页下钻、iframe / shadow DOM 里的列表、字体加密**。
5. **采集器默认会采进隐藏行**（C08 的 agent 指出的）。这次结果是对的，但遇到用隐藏元素放广告或占位的网站时会混进脏行。

## 结论

- **薄 skill 的方向在演练场上成立。** agent 直接读页面、自己写配置，盲测 14/14；同样这 14 个，引擎不调 AI 是 8/14，人工替引擎做选择也只有 10/14。差距集中在引擎「规则判断不了、产品里要靠 AI 兜底」的地方：选对列表、排除非数据行、跨页稳定的选择器、关掉弹窗。
- **「判断交给 agent、重复交给脚本」的分工有效。** 每个 agent 7–14 次工具调用就做完，没有一个是一页页手动翻的。多个 agent 还主动做了复核：试点一次再全量、加长等待复跑、抽查合并单元格的组内行。
- **成本结构变了。** 判断由用户自己的模型来做，约 10 万 token 一次；DataLens 不再出模型钱。
- **原型只有约 1100 行，不依赖插件的任何代码。**

## 下一步建议

1. **真实网站评测（最重要）**：用 `docs/real-site-walkthrough.md` 那套 227 站里挑 15–20 个有代表性的公开页面，同样盲测，人工核对字段。这能回答「同分布 14/14」在真实网站上剩多少。
2. **接用户自己的浏览器**：给 `browser.mjs` 加一个通过 CDP 连接已打开 Chrome 的模式，解决要登录的站。或者走插件的 MCP bridge，就是上一份报告里说的第三种组合。
3. **修已知问题**：隐藏行默认排除（加 `includeHidden` 开关）、详情页下钻、iframe。
4. 开源准备：README、许可证、`npm install` 后自带 Chromium 的说明。
